# Требования: Полная история диалога Work

## Описание
Реализовать чтение и отображение всей цепочки сообщений (user/assistant/result/system) из JSONL-файла сессии Work в хронологическом порядке. Сейчас `getLastResult()` читает только последний ответ — нужно расширить до полной истории.

## Требования
- **R1.** `WorkManager.getFullHistory(workId)` — читает весь JSONL-файл сессии, возвращает массив всех событий в хронологическом порядке (как есть в файле)
- **R2.** IPC-канал `work:history` — принимает `{ id }`, возвращает `{ messages: [...] }` 
- **R3.** Preload + `ipc-client.ts` — метод `workHistory(id)` на стороне рендерера
- **R4.** UI: в детальном view Work (состояние `AWAITING_INPUT` и `COMPLETED`) вместо блока `#last-result` показывать полную историю диалога:
  - Сообщения **user** — блок «You: <текст промпта>»
  - Сообщения **assistant** — переиспользовать `renderStreamEvent()` (text, thinking, tool_use)
  - Сообщения **result** — компактная сводка (turns, cost)
  - Сообщения **system/init** — заголовок «Session started · Model: X · Tools: N»
- **R5.** Сообщения отображаются в хронологическом порядке (сверху — старые, снизу — новые)
- **R6.** Блок с историей должен скроллиться независимо, если сообщений много

## Acceptance Criteria
- [ ] При выборе Work в статусе `AWAITING_INPUT` или `COMPLETED` отображается вся цепочка сообщений, а не только последний ответ
- [ ] Сообщения `user` отображаются с префиксом «You:» и текстом промпта
- [ ] Сообщения `assistant` корректно рендерятся через существующую логику `renderStreamEvent`
- [ ] Сообщения `result` показывают сводку (turns, cost)
- [ ] `system/init` отображается как заголовок сессии
- [ ] Если JSONL-файл не существует — показывается «(no history yet)»
- [ ] Если JSONL-файл содержит битые строки — они пропускаются с логированием в консоль
- [ ] История не ломается при переключении между Work'ами
- [ ] Для Work в статусе `IN_PROGRESS` продолжает работать live-режим `#stream-events` как раньше

## Особые сценарии
- **JSONL не существует:** Work только создан, ни одного run'а ещё не было → показывать «(no history yet)»
- **JSONL пуст:** Файл создан, но события не записаны → показывать «(no history yet)»
- **JSONL очень большой:** На MVP загружаем всё в память. При проблемах с производительностью в будущем — добавить пагинацию/виртуализацию
- **Битые строки в JSONL:** Некорректный JSON на какой-то строке → пропустить строку, `console.warn`, продолжить обработку остальных
- **Work в процессе выполнения:** Живой `#run-progress` / `#stream-events` имеет приоритет над историей — поведение не меняется
- **Переключение между Work'ами:** При выборе другого Work история предыдущего очищается и загружается заново
- **Формат user-сообщений:** В JSONL может быть `type: "user"` с `message.content` — нужно корректно извлечь текст
