# Claude Code Session Manager — Product Description

## Идея

Разработчик ведёт несколько проектов и в каждом пользуется Claude Code. Сессии копятся в `~/.claude/projects/`, их трудно отслеживать, а отвечать на результаты можно только из терминала. Session Manager — desktop-приложение, которое становится единым центром управления всеми задачами, порученными Claude Code.

**Ключевая механика:** каждое поручение Claude Code — это **Work**. Work состоит из цепочки **Run'ов** (запусков `claude -p`). Приложение запускает Claude Code в headless-режиме, показывает прогресс в реальном времени, а когда работа завершается — уведомляет пользователя и ждёт ответа. Разработчик управляет всеми задачами из одного окна, не открывая терминал.

**Ценность:**
- Все задачи перед глазами — не нужно помнить, в каком проекте и на какой ветке вы вчера работали с Claude
- Асинхронный режим — запустил задачу, переключился на другую, вернулся когда готово
- Структурированный прогресс — видно, что Claude читает файлы, о чём думает, что редактирует
- Безопасность — гибкая настройка разрешений для каждого проекта (Android-разработчику можно `gradlew`, фронтендеру — `npm`, а `rm -rf` запрещён всем)

## Функциональность

### Проекты
- Добавление существующего локального репозитория
- Клонирование удалённого репозитория (git clone)
- Создание нового пустого репозитория (git init)
- Для каждого проекта — автоматическая настройка разрешений Claude Code (`.claude/settings.json` + хуки)
- Преднастроенные профили разрешений: Android, Frontend, Python, Generic

### Work (задачи)
- Создание задачи: описание + имя git-ветки
- Автоматическое создание ветки от `main`/`master` и переключение на неё
- Запуск Claude Code: `claude -p "<описание>" --output-format stream-json`
- Прогресс в реальном времени: поток событий (думает → читает → редактирует → результат)
- По завершении Run — ожидание ответа пользователя
- Возобновление сессии: `claude --resume -p "<ответ>"`
- Отметка задачи как выполненной
- Удаление задачи вместе с JSONL-сессией

### Жизненный цикл Work

```
IN_PROGRESS  →  (Run завершился)  →  AWAITING_INPUT  →  (ответ пользователя)  →  IN_PROGRESS
                                          │
                                          └── (Mark Complete) → COMPLETED
```

### Безопасность и разрешения
- Глобальный `~/.claude/settings.json` и проектный `.claude/settings.json`
- Чтение файлов (Read, Glob, Grep) — авто-разрешено всегда
- Редактирование (Edit, Write) — авто-разрешено
- Bash: белый список по профилю (`gradlew`, `npm`, `pytest`), опасные команды (`rm -rf`, `git push --force`) запрещены, остальное — спрашивать
- Bash-классификатор через PreToolUse hook

### Обработка ошибок
- **Грязный репозиторий:** блокировка создания Work, диалог с возможностью Discard
- **Конфликт имени ветки:** ошибка с предложением другого имени
- **Git не установлен:** информативное сообщение
- **Watchdog:** если stdout молчит > N минут — процесс считается зависшим, принудительная остановка
- **Ручная остановка:** пользователь может остановить Run (SIGTERM → SIGKILL)
- **Перезапуск приложения:** все активные Run'ы корректно завершаются, при следующем старте — восстановление с пометкой

## User Stories

### US-01: Начало работы с новым проектом
> Как разработчик, я хочу добавить свой проект в Session Manager, чтобы Claude Code работал в нём с правильными разрешениями.

1. Открываю приложение, нажимаю «+ New Project»
2. Ввожу имя проекта, путь к локальному репозиторию, выбираю профиль «Android»
3. Нажимаю «Create»
4. Проект появляется в боковой панели. В директории проекта созданы `.claude/settings.json` и `.claude/hooks/classify-bash.sh` с whitelist'ом для `gradlew` и `adb`

### US-02: Первая задача
> Как разработчик, я хочу поручить Claude Code задачу и видеть, что он делает.

1. Выбираю проект в боковой панели
2. Нажимаю «+ New Work»
3. Ввожу описание: «Добавь экран авторизации с полями email и пароль»
4. Ввожу имя ветки: `feature/auth-screen`
5. Нажимаю «Create & Run»
6. Приложение создаёт ветку `feature/auth-screen` от `main`
7. Запускается Claude Code. Я вижу поток событий: system/init → assistant (думает) → tool_use (читает файлы) → tool_use (редактирует) → result
8. Через пару минут статус меняется на «Needs input», показывается результат

### US-03: Продолжение диалога
> Как разработчик, я хочу ответить Claude и уточнить задачу, не начиная с нуля.

1. Выбираю Work в статусе «Needs input»
2. Читаю последний результат — Claude создал экран, но использовал старую XML-вёрстку
3. Ввожу ответ: «Переделай на Jetpack Compose»
4. Нажимаю «Send»
5. Запускается новый Run с `--resume` — Claude помнит весь контекст и переделывает на Compose
6. Снова «Needs input» с новым результатом

### US-04: Несколько проектов одновременно
> Как разработчик, я хочу вести задачи в нескольких проектах и переключаться между ними.

1. Утром создаю Work в проекте «API Server»: «Добавь endpoint POST /upload»
2. Пока он выполняется, переключаюсь на проект «Mobile App»
3. Создаю там Work: «Обнови логику кэширования»
4. Оба Run выполняются параллельно (разные проекты, нет блокировки)
5. Вижу статус каждого Work в списке: зелёный «Running», оранжевый «Needs input», серый «Done»

### US-05: Грязный репозиторий
> Как разработчик, я хочу, чтобы приложение не дало мне случайно потерять незакоммиченные изменения.

1. Начинаю Work в проекте, где остались незакоммиченные правки с вечера
2. Нажимаю «Create & Run»
3. Появляется диалог: «Dirty Repository» со списком изменённых файлов
4. Варианты: «Discard Changes» (сбросить) или «Cancel» (отменить создание Work)
5. Нажимаю Cancel, делаю `git stash`, создаю Work снова

### US-06: Принудительная остановка
> Как разработчик, я хочу остановить задачу, если вижу что Claude пошёл не туда.

1. Work выполняется, вижу в потоке что Claude начал редактировать не те файлы
2. Нажимаю красную кнопку «Stop Run»
3. Процесс получает SIGTERM, через 5 секунд SIGKILL
4. Статус меняется на «Needs input» с пометкой «остановлено пользователем»
5. Могу перезапустить последний Run или ответить с уточнением

### US-07: Перезапуск приложения
> Как разработчик, я хочу закрыть приложение в любой момент и не потерять состояние задач.

1. У меня есть активный Run. Я закрываю приложение (Cmd+Q)
2. Все процессы Claude Code получают SIGTERM → SIGKILL
3. Состояние сохраняется в `session-manager.json`
4. Открываю приложение снова
5. Work, который был в процессе, теперь в статусе «Needs input» с пометкой «восстановлен после перезапуска»
6. Могу ответить или перезапустить Run

### US-08: Просмотр результата и завершение
> Как разработчик, я хочу посмотреть что сделал Claude и отметить задачу как готовую.

1. Выбираю Work в статусе «Needs input»
2. Читаю итоговый результат — Claude перечислил что изменил и какие файлы создал
3. Проверяю код в IDE, всё устраивает
4. Нажимаю «Mark Complete»
5. Work переходит в статус «Done» (серый badge), поле ответа скрывается
6. Ветка `feature/auth-screen` остаётся — я сам создам MR когда буду готов

### US-09: Настройка лимитов
> Как разработчик, я хочу контролировать расходы и количество ходов Claude Code.

1. Открываю Settings
2. Выставляю Max Turns = 15 (не хочу тратить больше 15 ходов на задачу)
3. Выставляю Watchdog Timeout = 5 минут
4. Сохраняю
5. Теперь каждый новый Run запускается с `--max-turns 15`
6. Если Claude замолчит на 5 минут — процесс будет принудительно остановлен

### US-10: Удаление проекта
> Как разработчик, я хочу убрать проект из приложения, когда он больше не нужен.

1. Навожу курсор на проект в боковой панели, появляется кнопка «×»
2. Нажимаю «×» → диалог подтверждения
3. Нажимаю «Delete»
4. Проект удалён из `session-manager.json`. Сами файлы проекта не трогаются.
5. Если у проекта были незавершённые Work — приложение не даст удалить, пока они не завершены или не удалены.
