# claus: Анализ концепции

> Проект **Session Manager** — единый центр управления задачами, порученными Claude Code.

## 2. Цель и ценность проекта

### 2.1 Что делает продукт?

Desktop-приложение (Electron), которое становится единым центром управления всеми задачами, порученными Claude Code. Разработчик добавляет локальные проекты, создаёт в них **Work** (задачи), приложение запускает Claude Code в headless-режиме (`claude -p`), показывает прогресс в реальном времени, а по завершении ждёт ответа пользователя и позволяет продолжить диалог (`--resume`) — всё без терминала.

### 2.2 Для кого предназначен?

Для разработчиков, которые используют Claude Code в одном или нескольких локальных проектах и хотят управлять задачами асинхронно, вне терминала. В частности — те, у кого сессии копятся в `~/.claude/projects/` и их трудно отслеживать, а ответы на результаты требуют открытого терминала.

### 2.3 Ключевая ценность для пользователя

- **Все задачи перед глазами** — не нужно помнить, в каком проекте и на какой ветке шла работа вчера.
- **Асинхронный режим** — запустил задачу, переключился на другую, вернулся когда готово.
- **Структурированный прогресс** — видно, что Claude читает файлы, о чём думает, что редактирует.
- **Безопасность** — гибкая настройка разрешений по проектам (Android → `gradlew`, frontend → `npm`, `rm -rf` запрещён всем).

## 6. Идея и концепция продукта

### 6.1 Проблема, которую решает (Было / Стало)

| Было | Стало |
|------|-------|
| Сессии Claude Code копятся в `~/.claude/projects/`, их трудно отслеживать | Все Work видны в одном окне, сгруппированы по проектам |
| Отвечать на результат можно только из терминала | Ответ отправляется из GUI, сессия продолжается через `--resume` |
| Прогресс задачи не виден структурированно | Поток событий в реальном времени: думает → читает → редактирует → результат |
| Права настраиваются вручную для каждого проекта | Автогенерация `.claude/settings.json` + hook, профили разрешений |
| Зависший run трудно контролировать | Watchdog-таймаут и кнопка принудительной остановки |

### 6.2 Ключевые концепции

| Концепция | Описание | Что даёт пользователю |
|-----------|----------|----------------------|
| **Work** | Одна задача, порученная Claude Code | Единица отслеживания и управления задачей |
| **Run** | Один headless-запуск `claude -p` внутри Work | Цепочка запусков образует непрерывный диалог |
| **AWAITING_INPUT** | Состояние Work после завершения Run | Сигнал «задача ждёт твоего ответа» |
| **Профиль разрешений** | Преднастроенный whitelist Bash по типу проекта | Безопасные права без ручной настройки |
| **PreToolUse-хук** | Bash-классификатор команд в `.claude/hooks/classify-bash.sh` | Тонкий контроль разрешений на уровне каждой команды |
| **Active Works** | Все незавершённые Work по всем проектам | Быстрый переход к активным задачам |

### 6.3 Что упрощает (Было / Стало)

| Было | Стало |
|------|-------|
| Запуск `claude -p` вручную в терминале для каждой задачи | Кнопка «Create & Run» в GUI |
| Отслеживание завершения — вручную, глазами | Статусы «Running» / «Needs input» / «Done» с badge |
| Ручная передача `--resume <session_id>` | Resume автоматически при повторном ответе |
| Опасение потерять незакоммиченные правки | Проверка dirty-repo с диалогом Discard перед запуском |
| Остаться с «осиротевшим» процессом при закрытии | Корректное завершение всех run + восстановление при старте |

### 6.4 Метафора продукта

**«Диспетчер задач для Claude Code».** Как менеджер задач (Jira/Todoist) для людей, Session Manager — это очередь поручений для ИИ-разработчика: вы раздаёте задания, следите за их выполнением в реальном времени, читаете результаты и при необходимости уточняете — а сам «исполнитель» (Claude Code) работает в фоне.

## 7. Потоки данных и бизнес-процессы

### 7.1 Основной use case (пошагово)

1. Пользователь добавляет проект: имя + путь + профиль (например, Android) + опционально `git init`.
2. Приложение генерирует в проекте `.claude/settings.json` и `.claude/hooks/classify-bash.sh` с whitelist'ом `gradlew`/`adb`.
3. Пользователь создаёт Work: описание задачи («Добавь экран авторизации»).
4. Приложение проверяет dirty-репозиторий; если есть изменения — диалог Discard/Cancel.
5. Запускается Run: `claude -p "<описание>" --output-format stream-json --verbose` в cwd проекта (команда запуска настраивается: `claude` / `claude-sm` / произвольная).
6. Renderer показывает поток событий: `system/init` → `assistant` (думает) → `tool_use` (читает/редактирует) → `result`.
7. Run завершается → Work переходит в `AWAITING_INPUT`, показывается последний результат.
8. Пользователь отвечает («Переделай на Compose») → новый Run с `--resume <session_id>`.
9. По завершении — «Mark Complete» → статус `COMPLETED`.

### 7.2 Жизненный цикл запроса/команды

**Статус-машина Work:**

```
IN_PROGRESS  →  (Run завершился)  →  AWAITING_INPUT  →  (ответ пользователя)  →  IN_PROGRESS
                                          │
                                          └── (Mark Complete) → COMPLETED
```

**Жизненный цикл Run (внутри `run-process.ts`):**

1. `spawn(command, args, { cwd })` — команда из настроек → открывается лог `<workId>.log`.
2. stdout разбирается построчно как `StreamEvent` (JSON); не-JSON игнорируется, stderr копится в хвост.
3. Watchdog: молчание дольше N минут → `timeoutOccurred` → отмена.
4. Обнаружение `AskUserQuestion` → `awaitingInput` → закрытие stdin.
5. Классификация выхода: `awaitingInput`→`ok`, `timeout`→`timeout`, `cancelled`→`stopped`, exit 0→`ok`, exit 127 или `ENOENT`→`config`, иначе→`error`.
6. События `run:started` / `run:event` / `run:completed` + `work:updated` уходят в renderer.

### 7.3 Интеграции с внешними системами

| Система | Тип | Протокол | Auth |
|---------|-----|----------|------|
| Claude Code CLI (`claude`, `claude-sm` или произвольная команда) | Дочерний процесс | `child_process.spawn`, stream-json на stdout | Локальная (без явной auth — использует окружение пользователя) |
| Git (`git`) | CLI | `execSync` (status/checkout/branch/clean/init/fetch) | Локальная (SSH/HTTPS пользователя) |
| Файловая система (`~/.claude/projects/<slug>/<uuid>.jsonl`) | Чтение файлов | JSONL | Локальная |
| MCP-серверы (имена из `~/.claude.json`) | Конфигурация | Чтение JSON-конфига | Локальная (имена серверов) |
| `jq` (внутри hook) | CLI | Пайп в сгенерированном Bash-хуке | — |
