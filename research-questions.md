# Claude Code Session Management — Research Questions

## Результаты исследования

### Вопрос 1: TTY vs pipe

**Ответ получен.** Claude Code имеет **два принципиально разных режима**:

| Режим | Флаг | TTY | stdin/stdout |
|-------|------|-----|-------------|
| Интерактивный | `claude` (по умолчанию) | **Требуется** (raw terminal mode) | Не работает через pipe |
| Headless | `claude -p` / `claude --print` | **Не требуется** | Чистый stdin → stdout |

**Вывод:** Для desktop-приложения используем **headless-режим** (`-p`). Он не требует TTY, работает как обычный subprocess с pipe, поддерживает `--output-format json` и `--output-format stream-json` (JSONL в реальном времени). Интерактивный режим можно не трогать вообще.

### Вопрос 2: Детект «паузы» / ожидания ввода

**Ответ получен.** В headless-режиме (`-p`) **нет пауз** — задача выполняется от начала до конца за один проход, после чего процесс завершается. Модель взаимодействия: «отправил prompt → получил результат → процесс вышел».

Это означает, что MVP нужно проектировать не как «долгоживущую интерактивную сессию», а как **«очередь одноразовых запусков с накоплением контекста»**. Механика:
1. Пользователь создаёт задачу → spawn `claude -p "..." --output-format stream-json`
2. Приложение читает JSONL-поток и отображает прогресс
3. Процесс завершается → сессия в статусе «требует внимания»
4. Пользователь отвечает → spawn `claude --resume <session_id> -p "ответ пользователя" --output-format stream-json`
5. Повторять до завершения задачи

Триггер «требует внимания» = процесс завершился (exit code), а не интерактивная пауза.

### Вопрос 3: Headless-режим и программный API

**Ответ получен.** Да, есть и то, и другое:

**Headless CLI** (`claude -p`):
- Запуск как subprocess, вывод на stdout
- `--output-format json` — полный JSON с `result`, `session_id`, `total_cost_usd`, `usage`
- `--output-format stream-json` — реальновременной поток JSONL
- `--json-schema` — строгая схема для структурированного вывода
- `--max-turns` (по умолчанию 25), `--max-budget-usd`
- `--allowedTools`, `--permission-mode` (default/acceptEdits/dontAsk/auto/bypassPermissions/plan)

**Agent SDK** (TypeScript/Python):
- Полноценный программный API: `query()`, `continue()`, `resume()`, `fork()`
- Hooks как колбэки (можно перехватывать, модифицировать, блокировать)
- Потоковая обработка сообщений: `for await (const msg of query(...))`
- Сложнее в развёртывании (нужен Node.js/Python проект)

**Рекомендация для MVP:** Начать с CLI `-p` + `stream-json` (меньше зависимостей, проще интеграция). При необходимости позже перейти на Agent SDK.

### Вопрос 4: Возобновление сессии

**Ответ получен.** Да, поддерживается:
- `claude --resume <session_id> -p "..."` — продолжить существующую сессию
- `claude -c` — продолжить последнюю сессию (алиас для `--continue`)
- В SDK: `continue()`, `resume()`, `fork()`

### Вопрос 5: Механика ввода-вывода

**Ответ получен.** В headless-режиме (`-p`):
- Один prompt → один запуск → полный вывод → процесс завершается
- Нет интерактивного цикла
- Поддерживается pipe: `cat prompt.txt | claude -p "$(cat)"`
- `stream-json` даёт построчный JSONL с прогрессом каждого шага

### Вопрос 6: Хранение истории сессии

**Ответ получен.** Claude Code хранит сессии на диске в следующей структуре:

**Путь:** `~/.claude/projects/{sanitized-project-path}/{session-uuid}.jsonl`

- Путь проекта санитизируется: не-алфанумерик символы заменяются на `-`
- Пример: `/Users/me/my-app` → `-Users-me-my-app`
- Session ID — UUIDv4 (например `31f3f224-f440-41ac-9244-b27ff054116d`)

**Формат:** JSONL (JSON Lines) — append-only, каждая строка = одно событие.

Типы событий: `user`, `assistant`, `system`, `summary`, `file-history-snapshot`, `custom-title`, `ai-title`, `last-prompt`, `tag`, `queue-operation`, `mode`, `agent-name`, `agent-color`.

**Связный список через parentUuid:** каждое сообщение ссылается на предыдущее через `parentUuid` → `uuid`. При возобновлении Claude Code walk'ает от последнего сообщения к корню, затем разворачивает цепочку для хронологии.

**Дополнительные данные сессии (по тому же UUID):**
- `~/.claude/file-history/{uuid}/` — бекапы изменённых файлов
- `~/.claude/todos/{uuid}-agent-*.json` — списки задач
- `~/.claude/debug/{uuid}.txt` — отладочные логи
- `~/.claude/history.jsonl` — глобальный индекс промптов по всем проектам

**Вывод для MVP:** Можно читать `{session-uuid}.jsonl` напрямую с диска без запуска процесса. Это решает отображение истории диалога. Более того, можно мониторить директорию `~/.claude/projects/` для обнаружения новых/активных сессий.

**Ограничения:**
- Сессии привязаны к абсолютному пути проекта. Перенос проекта = потеря связи с историей (если не симлинкнуть).
- Файлы сессий могут вырастать до гигабайт. У Claude Code есть режим «lite read» (первые + последние 64KB) для UI-превью — стоит перенять этот подход.
- OAuth-токены привязаны к хосту — нельзя просто скопировать файлы сессий на другую машину.

### Вопрос 10: Тонкая настройка разрешений через hooks/settings.json

**Ответ получен.** Да, тонкая настройка возможна через два слоя:

**Слой 1 — `permissions` в settings.json** (`~/.claude/settings.json` или `.claude/settings.json`):
```json
{
  "permissions": {
    "allow": ["Read", "Glob", "Grep", "Bash(gradlew *)", "Bash(npm run *)"],
    "deny": ["Bash(rm -rf *)", "Bash(git push --force *)", "Read(.env*)"]
  }
}
```
- Простой матчинг по glob
- `allow` всегда побеждает `ask` (внимание: если инструмент в обоих списках — авто-одобряется)
- Нет условной логики

**Слой 2 — Hooks `PreToolUse` / `PermissionRequest`:**
- Перехватывают каждый вызов инструмента
- Могут вернуть `permissionDecision: "allow"` / `"deny"` / `"ask"` через JSON на stdout
- Позволяют условную логику: проверить команду, путь, контекст → принять решение
- Поддерживают 4 типа обработчиков: `command`, `prompt`, `http`, `agent`

**Вывод:** Можно собрать нужную политику — «Edit авто, Bash(gradlew *) авто, остальной Bash спрашивать» — через комбинацию settings.json (грубо) + PreToolUse хук (точно). Desktop-приложение может управлять этими файлами.

**Важные ловушки:**
- `allow` отменяет `ask` — если инструмент попал в оба, молча автопринимается
- Матчеры чувствительны к регистру (`"bash"` не сработает на `Bash`)
- Claude может добавлять флаги к командам (например `git -C /path status` вместо `git status`)
